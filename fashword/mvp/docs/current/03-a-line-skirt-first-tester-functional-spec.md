# FASHword A라인 스커트 첫 테스터 기능명세서

## 1. 결정

FASHword의 첫 테스트 화면은 A라인 미디 길이 스커트 패턴 제작 과정을 돕는 Product Workspace다. 시안 방향은 Stitch Variant B - Product Workspace로 고정한다.

첫 테스터가 A라인 미디 길이 스커트 패턴을 실제로 제작한다. FASHword, LLM, 에이전트, UI는 최종 패턴을 대신 제작하지 않는다. 서비스는 치수와 제작 조건을 기록하고, 패턴 산출물을 확인하게 하고, 출력 준비와 제작 후 피드백을 구조화해 다음 보정으로 이어주는 작업공간이다.

## 2. 서비스 이해

FASHword는 AI가 사진 한 장으로 봉제 가능한 패턴을 자동 완성하는 서비스가 아니다. 최신 기준은 의상 패턴 제작 규칙을 실행 가능한 기하 로직으로 변환하고, 사람이 검토할 수 있는 패턴 출력과 제작 후 피드백 루프를 만드는 AI Pattern Compiler다.

첫 PoC의 목적은 A라인 미디 길이 스커트 원형/패턴 흐름을 통제된 범위에서 검증하는 것이다. 스커트는 체촌 입력이 비교적 적고, 허리/힙/다트/옆선 검산이 가능하며, 테스터가 실제 출력 후 제작 테스트를 수행할 수 있기 때문에 첫 실증 대상으로 적합하다.

## 3. 범위

### 포함

포함 범위는 Dashboard, Product Workspace, 치수 입력, 몸/핏 조건 기록, A라인 미디 길이 스커트 패턴 보기, 3D로 보기, 출력 준비, 제작 체크리스트, 제작 후 수정 기록, Correction Log 초안이다.

프로토타입은 정적 mock 기반이어도 된다. 단, 화면의 의미는 명확해야 한다. 사용자가 "서비스가 패턴을 만들어준다"가 아니라 "내가 제작할 패턴과 제작 기록을 관리한다"고 이해해야 한다.

### 제외

실제 패턴 계산, 실제 SVG/PDF 다운로드, 서버 저장, 로그인, 결제, 가격제, 유료 검수, 구독, 원격 동기화, 실제 3D 렌더링, 실제 가상 피팅 정확도 판정은 제외한다.

## 4. 사용자

### 첫 테스터

첫 테스터는 A라인 미디 길이 스커트 패턴을 출력하고 제작 테스트를 수행할 사람이다. 이 사용자는 개발자 용어보다 오늘 해야 할 일, 필요한 치수, 출력 전 확인 사항, 제작 후 남길 피드백을 알고 싶어 한다.

### 내부 운영자

내부 운영자는 FASHword 기획자, 패턴 전문가, 개발자다. 이들은 테스터가 남긴 치수, 제작 조건, 출력 준비 상태, 피드백을 보고 다음 보정 후보를 판단한다.

## 5. 화면 구조

| View | 목적 | 핵심 기능 |
| --- | --- | --- |
| Dashboard | 현재 A라인 스커트 테스트 프로젝트와 다음 작업을 보여준다. | 프로젝트 카드, 진행률, 작업공간 열기 |
| Workspace | 제작 흐름 전체를 한 화면에서 관리한다. | 오늘 할 일, 진행 상태, 패턴 보기, 3D로 보기, 출력 준비, 제작 후 기록 |
| Making Notes | 제작 후 피드백을 구조화한다. | 불편 부위, 제작 메모, 다음 보정 후보 기록 |

라우터는 필수가 아니다. 첫 구현은 local state로 Dashboard와 Workspace를 전환한다.

## 7. Dashboard 기능

Dashboard는 첫 테스터가 앱에 들어왔을 때 현재 진행 중인 A라인 스커트 테스트를 확인하고 Workspace로 진입하는 화면이다.

| ID | 기능 | 설명 | 수용 기준 |
| --- | --- | --- | --- |
| DASH-01 | 프로젝트 카드 | `A라인 스커트 첫 테스트` 프로젝트를 보여준다. | 의복명, 최근 수정일, 현재 단계가 보인다. |
| DASH-02 | 다음 작업 | 오늘 이어서 할 작업을 보여준다. | 치수 확인, 패턴 보기, 출력 준비, 제작 기록 중 하나가 강조된다. |
| DASH-03 | 진행률 | 전체 제작 준비 흐름의 진행률을 보여준다. | 개발 진행률이 아니라 테스터 작업 진행률로 읽힌다. |
| DASH-04 | 작업공간 열기 | Workspace로 이동한다. | 버튼 클릭 후 Workspace가 표시된다. |

## 8. TopBar 기능

TopBar는 현재 작업 대상과 주요 명령을 고정해서 보여준다.

| ID | 기능 | 설명 | 수용 기준 |
| --- | --- | --- | --- |
| TOP-01 | 브랜드 | `FASHword`를 보여준다. | 모든 화면 너비에서 브랜드가 보인다. |
| TOP-02 | 현재 의복 | `A라인 미디 스커트`를 기본값으로 보여준다. | 린넨 셔츠, 블라우스 등 다른 의복명이 나오지 않는다. |
| TOP-03 | 기록 저장 | 화면 내 mock 상태를 저장한 것처럼 피드백한다. | 실제 서버 저장처럼 과장하지 않는다. |
| TOP-04 | 제작 기록 확인 | 현재 제작 기록 상태 문구를 갱신한다. | 시스템이 패턴을 제작한다는 뉘앙스가 없다. |

## 9. Today Tasks 기능

오늘 할 일은 첫 테스터가 다음 행동을 잃지 않도록 안내한다.

권장 작업은 치수 확인, 몸/핏 조건 확인, A라인 스커트 패턴 보기, 출력 준비, 제작 후 수정 기록이다.

| ID | 기능 | 설명 | 수용 기준 |
| --- | --- | --- | --- |
| TASK-01 | 작업 목록 | 3~5개의 행동 단위 작업을 보여준다. | 항목이 명사 나열이 아니라 실제 행동으로 읽힌다. |
| TASK-02 | 상태 | 완료, 진행 중, 다음 상태를 보여준다. | 색상 없이도 상태가 전달된다. |
| TASK-03 | 현재 작업 강조 | 현재 필요한 작업을 강조한다. | 사용자가 다음 행동을 바로 알 수 있다. |

## 10. Progress 기능

진행 상태는 패턴 생성 진행률이 아니라 제작 준비와 제작 후 기록 흐름을 보여준다.

권장 단계는 치수 확인, 몸/핏 조건, 패턴 확인, 3D로 이해하기, 출력 준비, 제작 후 수정 기록이다.

| ID | 기능 | 설명 | 수용 기준 |
| --- | --- | --- | --- |
| PROG-01 | 단계 표시 | 6단계 제작 흐름을 보여준다. | 현재 위치와 다음 단계가 명확하다. |
| PROG-02 | 출력 전 상태 | 패턴 보기 이후 출력 준비가 필요함을 보여준다. | 바로 제작하라는 압박이 아니라 준비 흐름으로 보인다. |
| PROG-03 | 제작 후 기록 연결 | 출력/제작 이후 수정 기록으로 이어진다. | FASHword의 핵심이 피드백 루프임이 드러난다. |

## 11. Measurement 기능

치수 입력은 A라인 스커트 첫 테스트에 필요한 하의 중심 항목만 둔다.

필수 항목은 허리둘레, 엉덩이둘레, 허리에서 엉덩이까지, 스커트 길이, 여유량이다.

| ID | 기능 | 설명 | 수용 기준 |
| --- | --- | --- | --- |
| MEAS-01 | 치수 입력 | 필수 치수를 입력하거나 mock 값으로 확인한다. | 모든 input에 visible label이 있다. |
| MEAS-02 | 단위 | cm 단위를 표시한다. | 사용자가 단위를 추측하지 않는다. |
| MEAS-03 | 변경 반영 | 값을 바꾸면 화면 상태가 유지된다. | 실제 패턴 재계산처럼 과장하지 않는다. |
| MEAS-04 | 기록 저장 | 치수 기록 저장 상태를 보여준다. | 서버 저장이 아닌 프로토타입 상태 피드백이다. |

## 12. Body/Fit Conditions 기능

몸/핏 조건은 테스터의 제작 조건과 착용 이슈 가능성을 중립적인 언어로 기록한다.

권장 항목은 허리선이 앞쪽에서 올라감, 복부 여유 필요, 엉덩이 뒤쪽 여유 필요, 좌우 차이 확인 필요, 원하는 스커트 길이 확인이다.

| ID | 기능 | 설명 | 수용 기준 |
| --- | --- | --- | --- |
| BODY-01 | 조건 chip | 몸/핏 조건을 chip으로 표시한다. | 병명, 평가, 비난처럼 읽히지 않는다. |
| BODY-02 | 선택 토글 | chip을 선택/해제한다. | `aria-pressed`와 시각 상태가 함께 바뀐다. |
| BODY-03 | 선택 요약 | 선택 조건이 제작 기록에 반영됐다고 보여준다. | 사용자가 기록 상태 변화를 알 수 있다. |

## 13. Pattern View 기능

패턴 보기는 테스터가 제작할 A라인 스커트 패턴 조각을 확인하는 화면이다. 패턴을 에이전트가 제작했다는 표현을 쓰지 않는다.

| ID | 기능 | 설명 | 수용 기준 |
| --- | --- | --- | --- |
| PATT-01 | 스커트 조각 표시 | mock SVG로 앞판과 뒤판을 보여준다. | 허리선, 힙선, 중심선, 다트 위치가 보인다. |
| PATT-02 | 조각명 | 조각 이름을 사용자 언어로 보여준다. | 앞판, 뒤판, 허리선, 힙선처럼 표시된다. |
| PATT-03 | 상태 문구 | 제작 전 확인 상태를 보여준다. | 계산 완료나 AI 생성 완료처럼 과장하지 않는다. |
| PATT-04 | 출력 준비 연결 | 출력 전 확인 카드로 자연스럽게 이어진다. | 패턴 보기가 최종 완료처럼 보이지 않는다. |

## 14. 3D로 보기 기능

3D로 보기는 입체 형태 이해를 돕는 보조 화면이다. 핏 정확도 검증이나 가상 피팅 성공 판정이 아니다. 다만 장기 방향은 게임 엔진의 캐릭터-의상 처리 방식을 차용한다. 체촌값으로 단순 바디 프록시를 만들고, 사용자가 앞/뒤 도식화에서 컨펌한 허리선·힙선·길이·밑단폭 정보를 스커트 프록시에 반영해 몸 위에 얹어 보여준다. MVP에서는 Blend Shape, Bone Scale, Skinning, Cloth Simulation 같은 용어와 실제 물리 시뮬레이션을 노출하지 않고, 같은 패턴 계산값에서 나온 검산용 3D 피팅 프록시와 상태 색상만 제공한다.

| ID | 기능 | 설명 | 수용 기준 |
| --- | --- | --- | --- |
| VIEW-01 | 3D placeholder | 스커트 실루엣 또는 바디-패턴 관계를 시각적으로 보여준다. | 실제 착용 정확도를 보장하지 않는다. |
| VIEW-02 | 한계 고지 | 최종 핏은 실제 제작 후 기록으로 확인한다고 말한다. | 안내 문구가 화면 안에 고정된다. |
| VIEW-03 | 장기 확장 여지 | 향후 3D/virtual try-on 실험과 연결될 수 있음을 내부적으로 남긴다. | 현재 구현 기능처럼 노출하지 않는다. |
| VIEW-04 | 바디-스커트 프록시 | 입력 치수 기반 바디 실루엣과 A라인 스커트 프록시를 겹쳐 보여준다. | 허리·힙·옆선 상태가 색상과 짧은 문구로 표시된다. |
| VIEW-05 | 도식화 컨펌 연결 | 앞/뒤 도식화에서 확인한 길이, 허리선, 힙선, 밑단폭이 입체 프록시의 기준임을 내부 명세로 남긴다. | 화면에는 "도식화 기준 형태"처럼 사용자 언어로만 표현한다. |

## 15. Output Prep 기능

출력 준비는 테스터가 패턴을 출력하기 전에 확인해야 할 항목을 정리한다.

권장 항목은 용지 크기, 페이지 나눔, 기준선 확인, 스케일 확인, 제작 전 체크리스트다.

| ID | 기능 | 설명 | 수용 기준 |
| --- | --- | --- | --- |
| OUT-01 | 출력 체크 | 출력 전 확인 항목을 보여준다. | 실제 파일 다운로드처럼 보이지 않는다. |
| OUT-02 | 스케일 주의 | 출력 스케일 확인 필요성을 알려준다. | 겁주는 경고가 아니라 제작 준비로 읽힌다. |
| OUT-03 | 제작 전 연결 | 출력 후 제작 체크리스트로 이어진다. | 다음 행동이 명확하다. |

## 16. Making Checklist 기능

제작 체크리스트는 테스터가 A라인 스커트를 실제 제작하기 전후에 확인할 항목을 제공한다.

| ID | 기능 | 설명 | 수용 기준 |
| --- | --- | --- | --- |
| MAKE-01 | 제작 전 확인 | 원단, 재단, 기준선, 허리/힙 위치를 확인한다. | 패턴 전문가 용어보다 제작 행동 중심이다. |
| MAKE-02 | 제작 중 메모 | 제작 중 이슈를 짧게 남길 수 있게 한다. | 실제 저장 없이 mock 메모여도 된다. |
| MAKE-03 | 제작 완료 표시 | 제작 테스트 완료 상태를 표시한다. | 완료가 핏 성공을 의미하지 않는다. |

## 17. Making Notes / Correction Log 기능

제작 후 수정 기록은 FASHword의 핵심 기능이다. 패턴 파일보다 중요한 것은 제작 결과와 수정 이력이 다음 보정으로 이어지는 구조다.

| ID | 기능 | 설명 | 수용 기준 |
| --- | --- | --- | --- |
| NOTE-01 | 불편 부위 기록 | 허리 뜸, 힙 당김, 다트 위치, 옆선 불균형 등을 기록한다. | 테스터가 쉬운 말로 선택하거나 입력할 수 있다. |
| NOTE-02 | 제작 조건 기록 | 원단, 재단, 봉제 중 특이사항을 기록한다. | 패턴 자체 문제와 제작 변수를 분리할 수 있다. |
| NOTE-03 | 다음 보정 후보 | 다음에 확인할 보정 후보를 표시한다. | 전문가 검토 전 확정값처럼 보이지 않는다. |
| NOTE-04 | 내 핏 기록 | 반복 제작에 활용될 기록임을 보여준다. | `fit data`라는 내부 용어를 쓰지 않는다. |

## 19. 상태 모델

필수 상태는 `activeView`, `testerProject`, `measurements`, `bodyFitConditions`, `patternStatus`, `saveStatus`, `makingNotes`, `activePreviewMode`다.

`activePreviewMode`는 `patternView`와 `shapePreview`만 사용한다. 화면에는 `패턴 보기`, `3D로 보기`로 표시한다.

## 20. 수용 기준

기능 수용 기준은 Dashboard에서 Workspace로 이동할 수 있고, Workspace에서 A라인 스커트 제작 준비 흐름이 오늘 할 일, 진행 상태, 패턴 보기, 3D로 보기, 출력 준비, 제작 체크리스트, 제작 후 수정 기록으로 이어지는 것이다.

문구 수용 기준은 화면이 "AI가 패턴을 만들어준다"로 읽히지 않는 것이다. 첫 테스터가 제작 주체이고 FASHword는 기록과 검증 흐름을 돕는다는 점이 명확해야 한다.

검증 수용 기준은 `npm run build` 통과, 주요 `data-testid` 부착, 데스크톱/모바일 실제 화면 확인, 금지 용어 스캔 통과다. UI/UX 완료는 빌드 성공만으로 선언하지 않는다.

## 21. 구현 순서

1. mock 데이터와 타입을 A라인 스커트 기준으로 교체한다.
2. Dashboard의 프로젝트명을 A라인 스커트 첫 테스트로 고정한다.
3. TopBar 버튼을 `패턴 만들기`가 아니라 `제작 기록 확인` 또는 `기록 저장` 중심으로 바꾼다.
4. 치수 항목을 허리, 힙, 허리-힙, 스커트 길이, 여유량으로 제한한다.
5. Pattern View를 스커트 앞판/뒤판 SVG로 바꾼다.
6. 3D로 보기는 검산용 바디-스커트 프록시로 확장한다. 허리, 힙, 옆선 상태는 draft report의 pass/fail 결과를 기준으로 표시한다.
7. Making Checklist와 Making Notes를 추가한다.
8. 금지 문구와 수익모델 문구를 스캔한다.
9. 데스크톱/모바일 브라우저 화면 증거를 남긴다.
